## 2. Helper adoption and friction

### Used successfully

- **`SessionHelpers.runBrowserCheck` / `runCheck` + `Project.CheckResults`:** root's baseline browser and scaffold checks returned 1/1, exact source, original job, and clean terminal evidence. New and integrated Engine/cancellation/reopen checks reused `runCheck`/focused result flows. `docs/automation-trials.json` wave18 records original jobs and source/count/cleanup outcomes. The typed path removes manual count parsing in successful use.
- **`preflightSlice` (root-invented notebook helper):** exact type/body and limits are retained in `docs/wave18-design-followup.md` §1. It checks base ancestry, owned paths, `merge-tree`, preserves all receipts, and performs no merge/approval. Reused on UI, Runtime, Engine, cancellation and final slices. Successful runs still execute four Git jobs; no refusal path was exercised in the two design-note examples and no round savings are measured.
- **`reload_helpers`:** after root's disk-present but unbound `SessionHelpers` import failure, root explicitly published helper source `ec811751…` over `50b4f8a…`; the same browser cell succeeded. See rollout root ordinals 43/45/50 and `docs/wave18-execution.md`. This is successful recovery, with a one-time setup cost.

### Missed, skipped, reasonably avoided, or unproven

- **Review packet/helper adoption was missed:** reviewer13 chose direct shell/Cargo commands despite typed `FocusedResult` and `runCheck` being available in the workspace menu; exact memory/build environment was not packaged. The source proves an easier path existed, not that it was in the reviewer's bound imports. Improvement owner: existing check/review owners (`SessionHelpers`, `Project.ReviewFlow`), not a parallel result parser.
- **The read-only Runtime and Browser discovery leaves reasonably skipped helper execution:** their trace assignments were findings-only and no test/check was authorized. Interviews at `docs/interviews.md` wave18 discovery actors 4 and 5 explicitly say no helper invocation; setup/reload would not create evidence for source reading. This is not non-adoption failure.
- **`runBrowserCheck` did not substitute for the expected-red barrier:** the early Operator response was docs-only while production producer was absent; the BrowserInvestigation/check helpers cannot invent the producer or settle its protocol. Root's bounded manual trigger and expected-red requirement were appropriate. No check helper should claim production acceptance before the consumer exists.
- **`Project.Merge.mergeInto` was reasonably avoided:** inspection found reset-hard rollback on a red integrated check, forbidden by this run's preservation policy. Root used reviewed ordinary merges. Owner is `Project.Merge`; no destructive helper execution occurred.
- **No generic Watchdog benefit is attributable in these traces:** the Jev cost report separately analyzed root and sampled annotations. This audit does not rerun that work. Root's checklist nudge was a specialized WorkflowReminders trial, not evidence for generic after-tool supervision.

### Savings: observation vs inference

**Observed:** typed checks retained count/source/job/cleanup; `preflightSlice` replaced repeated *manual preflight logic* while still running four commands; the router was changed to suppress routine raw-candidate notifications; exact same candidate/job handles were retained through check collection and repair. Several failures were recovered without rerunning product tests.

**Not measured / inference only:** saved model rounds, elapsed time, tokens, or causal benefit from the reminder. No helper invocation count is a savings measure. The 90-turn root and three child rollouts include parallel work and coordination, not a counterfactual baseline. The root trace still shows manual relay, receipt interpretation and root semantic integration decisions after helpers ran.

## Ownership summary

- Candidate/check/review continuation and memory/build configuration: `SessionHelpers` + `Project.TestEvidence`/`Project.CheckResults` + `Project.ReviewFlow`.
- Mutable notice policy and typed reviewed checkpoints in the existing collector: `Project.Routing`/`Project.Work`.
- Question revision, message presentation, acknowledgment and incorporation: existing `Project.Routing`/actor question flow; do not combine those facts into one receipt.
- Git scope/ancestry integration policy: `Project.Merge` and root integration owner; keep destructive rollback opt-in.
- Baseline-descendant acceptance predicate: existing `Project.BaselineIncorporation`; current exact-head restriction was inspected, not live-refused in this sample.
- Browser B trigger and production acceptance: standalone producer plus Operator consumer owners; Haskell continuation can stage the agreed path but must interrupt unresolved contract decisions.
