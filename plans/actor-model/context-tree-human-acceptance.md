# Human acceptance: inhabit a tree of work

Status: guide ready; the actual campaign is human-run and not yet recorded.
Use the user's small TUI application repository and a bounded useful feature
or defect. Do not supply a campaign Haskell module or prescribe decomposition.
Record the Tidepool revision, Codex revision, project model/effort configuration,
and the task. Use an isolated source checkout and retain Git evidence.

## Exercise

Let the root discover useful Haskell and make a concrete scaffold. Observe a
writable coordinator editing its own worktree, recursively unfolding, folding
Git changes, and running a second local cycle. Let the model choose its types,
helpers, child count, review method, and when more thinking is useful.

Retain a specialist for a follow-up containing a new evidence/decision delta.
Review an exact candidate head and refine it. Inspect heterogeneous settled
results more than once. Introduce one bounded failure journey, such as a
request deadline, stopped actor, dirty seed, stale notification, or merge
requiring ordinary Git. Complete integration and deliberately clean up only
contexts that no longer help. Verify worktrees and Git history survive.

When fork-time effort support is available, include a high-effort parent and
an explicitly low-effort child. Until the Codex integration is ready, record
this portion as unverified rather than instructing a model to emulate it.

## Evidence and judgment

Record inherited declarations and full-call context, exact parent/child provider
lineage, cache boundary observations, distinct lexical scopes, and scoped
cached/uncached input counts. Cache percentage alone is not inheritance proof.
Do not infer missing provider data. The model should not need pane archaeology
to decide which typed handle to poll or which request it still owes.

Ask where the model spent attention accommodating the harness. Did a scaffold
communicate decisions better than another assignment essay? Did a useful local
abstraction emerge? Did retained expertise and fresh forks serve different
needs? Could lower-effort descendants use the same surface? Could the model
resume useful thought immediately after waking?

Report task outcome, invented patterns, orchestration repairs, context
retelling, confusing failures, and remaining unknowns. Do not require artificial
complexity merely to tick a scenario box. This exercise establishes efficacy;
it does not replace deterministic settlement, authority, or cleanup checks.
