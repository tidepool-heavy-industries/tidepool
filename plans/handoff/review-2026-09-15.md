## Blocking fixes (peer-amended)

Amendments from the second reviewer (2026-09-15) change three of the original
proposals and are the governing versions:

- **Daemon settlement stays indeterminate.** A clean EOF before the acceptance
  marker, or a failed client write after any request bytes may have reached
  the daemon, does not prove rejection: the daemon may have accepted and acted
  before dying, and a retry could replay. `NotAccepted` only comes from an
  explicit `REJECTED` frame or a failure before connection/transmission.
  Rotation is fixed on the daemon side: every exit path drains connected
  clients through `OwnedSocket::retire` and sends `REJECTED` before closing,
  including the partial-client window.
- **Stale socket recovery needs owned identity.** No unlink on one refused
  connect. The daemon holds an `flock`ed lock file for its life and records
  the socket's `(dev, ino)`; on `AddrInUse` it takes the lock non-blocking,
  preflights, and unlinks only if the path's identity is unchanged.
- **Fail-closed typed sites are an elaborator invariant**, not a post-hoc
  scan: every prepared-verb occurrence in a binding is classified exactly
  once — rewritten, or recorded as a deferred `SiteRejection`
  (`CastInSpine`, `UnclassifiedOccurrence`). Reachability scoping then keeps
  dead bindings and retained imports unrejected and legitimate closable
  first-class uses rewritten.
- **Descriptor interning is a machine-owned compile reservation**, not a
  carried snapshot: outstanding compiles share canonical descriptors or the
  second install gets a typed `StaleReservation`.
- **Byte pools go behind one machine-owned address resolver** used by both
  observation and the string primops; pool collections are not threaded
  through call sites.
- **ROOT refusal lives in `ResourceLedger::close_realm`**; runtime/machine
  guards remain presentation.
- **`:lineage`**: do not restore the deleted combined `:status\n:lineage`
  submit (status and lineage moved to structured routes); cover lineage
  through the current HTTP/actor graph route after locating its consumer.
- **Corpus-oracle integrity is blocking**: `check` validates a committed
  digest over the complete oracle payload; `verify` regenerates and compares;
  the gate caps `no_oracle` or checks its identity set; the evaluation
  timeout and tool versions are fingerprinted.
- **`CallerResult` offer set**: record the offered instances explicitly
  before changing the seed; demands must include PAP completion, joins,
  imports and retained callers.

All blocking items are closed: typed-site classification `e50831879`, ROOT
refusal and the reservation test `6567074d9`, daemon settlement and endpoint
lock `04e59d567`, oracle seal `0870da4ff`, machine-owned address resolver
`79e426ce9` (ten host functions, not three). One amendment reversed during
implementation: a separate "used as a value" rejection was dropped because
GHC eta-reduces polymorphic aliases to bare verb references, where the
unresolved-result-type advice is the right one. The full prepared corpus
passes with these changes (see `implementation-2026-09-15.md`).

Item 10 closed without a change: lineage's production consumer is the status
tool's `lineage` view (`tidepool-actor/src/status_tool.rs:88`), covered end to
end at `tidepool/src/actor_host.rs:8255-8269`, which asserts seven lineage
fields. The workbench keeps `lineage` only in its observational command set
(`tidepool-runtime/src/session/workbench.rs:536`).

Item 6 needs no code change: every program has at least one top slot and
`install_staged` checks the slot base before absorbing descriptors, so the
slot base is the compile reservation. A second outstanding compile is refused
with `TopSlotBaseMismatch` before any side effect; a test pins this.

The ordered list with tests is in the session plan and mirrored into
`implementation-2026-09-15.md` as fixes land.

# Review: 186d8d12c (install/address) + e69d28717 (custody)

**VERDICT: Accept with follow-ups.** Both fixes authenticate rather than widen;
the install transaction closes audit §"Machine install failure paths" 1-4 and
the ROOT guard closes §"PreparedRuntime session invariants" 1. Three medium
gaps remain: staged-interner descriptor divergence, ROOT guard placed above the
mechanism, and a pool-union asymmetry between observation and the string primops.

## Findings

### Medium — staged interner can break machine-wide descriptor sharing
`tidepool-codegen/src/prepared_program/machine.rs:352-358` now compiles against
`self.interner.clone()` and discards it. `interner.rs:1-11` states the whole
invariant: generated dispatch compares the pinned `ObjectDescriptor` *address*,
so one identity must have one Arc machine-wide. Compile→install→compile is safe
(the second clone already carries the absorbed Arc). Two `compile_for_install`
calls *before* either install both mint fresh Arcs for a shared new identity;
`absorb` (`interner.rs:82-86`) `or_insert`s, keeping A's Arc while B's code has
B's baked in. Result is silent mis-dispatch (Case falls to default), not a trap.
Fix: carry the staged interner with the `CompiledProgram` and absorb *it* at
install, or `debug_assert` that no compile is outstanding. Test: compile two
programs sharing a new constructor before installing either; assert equal
descriptor pointers or a typed refusal.

### Medium — ROOT guard is above the mechanism
Guards added at `tidepool-runtime/src/session/prepared.rs:662-670` and
`tidepool-codegen/src/prepared_program/machine.rs:829-832`. Unguarded below:
`tidepool-codegen/src/resource_ledger.rs:210` (`ResourceLedger::close_realm`)
and `tidepool-codegen/src/jit_machine.rs:2916`, which
`tidepool-runtime/src/session/resident.rs:1091` reaches with a caller-supplied
realm (its `machine_mut` is `persistent.rs:273` → `JitEffectMachine`). The audit
itself said "runtime or ledger". Per repo rule "one implementation", put the
refusal in `ResourceLedger::close_realm` and leave the upper layers as
pass-throughs. Test: `JitEffectMachine::close_realm(ROOT)` keeps ROOT handles.

### Medium — observation unions pools; the primops do not
`observe.rs:495-508` searches every installed program's pool. The primops
(`static_bytes.rs:160-168, 236-238, 296-308`) still see only the single `pool`
Arc baked in at codegen, then fall back to the ledger. A literal `Addr#`
produced by program A, imported by B, and passed to `unpackCString#` /
`indexCharOffAddr#` in B misses both and returns `BadPointer` — which latches.
Fix: hand the primops the machine-wide `pools` vector (it now exists at
`machine.rs:144`) or resolve through vmctx. Test: the new cross-program fixture
in `bytes_tests.rs:583-655`, but calling `prepared_c_string_len` on the imported
address instead of observing it.

### Low — first-program rollback branches on the wrong predicate
`machine.rs:265-273`: `owners.is_none()` is used as a proxy for "first program"
and triggers `clear_gc_state()`, which would destroy a live heap if prepared GC
substate were ever absent on a populated machine. Branch on
`self.programs.is_empty()` instead. Related: the old `free_session_heap()` /
`clear_persistent_roots()` on that path is gone; correctness now rests entirely
on the transaction slot range covering every root `install` registers — true
today (`publish_imports` and the heap-top loop both write inside
`claimed_slots..claimed_slots+slot_count`), but undocumented as a load-bearing
invariant.

### Low — install now begins a prepared call
`machine.rs:398-400`: `install_program` on an `Unavailable` machine now returns
`ExecutionError::Runtime(last_failure)` instead of its previous error. Correct,
but the doc at `machine.rs:366-380` does not say so.

### Low — `insert_idle` still moves the machine by value
`registry.rs:205-215` takes `M` and boxes inside; `harness.rs:993` and
`resident_workbench.rs:6426` still build a `Session` on the caller's stack. The
new test itself does this on the main thread. Take `Box<M>`.

### Nit — rationale deleted
`registry.rs:507-509`: the rewritten comment drops why `assert_not_impl_any` is
pinned at `M = H = ()`. The `Checkout` `Drop` doc rewrite is accurate (the impl
at `registry.rs:594-605` is unchanged and does restore).

## Checked clean

  nearest preceding literal by base and returns `storage.get(offset..logical_len)`:

  slice, the trailing NUL and any inter-allocation gap are rejected, `0` and
  `usize::MAX` are rejected. Observation **never** dereferences without a pool hit

- **Primops authenticate, not widen.** All three fall back to `MachineState`

  the *same* published allocation. `external_c_string_len`'s
  `record.logical_len - offset` cannot underflow given that invariant, and a
  missing NUL is an error rather than an over-read. Untracked addresses still

  `register_prepared_entries`/`programs`/`claimed_slots` all mutate after the last
  fallible step. No partially installed program is reachable from dispatch or
  resolution tables. `Reusable` now matches reality: the added assertions prove
  `retain_top` and a *fresh install* both succeed with no `run_entry` between.
  Relocation from a completed `collect_on` is deliberately not undone — correct,
