Scope: the ownership and transport changes in `LIVE-COMPLETION.md`, including
complete finite-notebook retirement. Ordinary native compilation, bootstrap,
parser-only cell planning and activation preview remain supported production
consumers. They are not permission to restore the deleted notebook path.

The purpose of this gate is to establish the rebuilt region's contracts, then
observe whether G2 progresses. A local pass does not establish G2 or G3, and a
later G2 failure does not by itself locate a defect in this region.

## Sequence

1. Compile the joined production and test consumers with the pinned toolchain.
   The current 32-target queue includes Rust runtime, toolchain, actor and
   extractor consumers plus the changed Haskell worker and three test binaries.
   Compile any additional target selected by the regional matrix before execution.
2. Run the existing 15-case repair shortlist for fast feedback. Then execute the
   nonoverlapping regional controls, retaining discovered, selected and executed
   counts independently. No zero-match or compile-only acceptance.
3. Independently review joined dataflow, failure paths, test sensitivity and
   migration completeness. A search for old names alone is insufficient. Repairs
   require affected compilation, discriminating tests and another scoped review.
4. Close the region only when no unresolved in-scope finding remains and every
   required selected case has actual passing evidence on the joined candidate.
   Record intentional exceptions and evidence limits explicitly.
5. Run the maintained G2 histories through the production path. Record actual
   values, effects, publication and cleanup, as well as the first failing boundary.
   A different error is progress evidence only when the preceding behavior is
   observed. Do not weaken authorization or reintroduce old APIs to advance G2.

## Required relationships

- Selected implementations retain their actual acquisition, exact dependency
  edges and source evidence. Equal bytes, custody and executable permission stay
  distinct. Future values and crossed owners must refuse.
- Pending drafts become captured products through the actual compiler stage;
  World item selection carries its advancing prefix. Test fixtures cannot issue
  successful World or SOURCE authority by fabricating receipts.
- Package additions survive actual item selection and later requests, not only
  packet encoding. Checked values retain their actual output and backing.
- Materialization and prepared transport retain exact files for the consumer's
  lifetime and release them at the owning boundary, including interruption.
- Compiler roles apply at their owning namespace, independently of physical
  custody. Receiving precedence, aliases, exact source relocation and separate
  equal-byte issuers require positive and negative controls.
- Both protocol decoders refuse the removed notebook operation while preserving
  parser-only planning and current ordinary/World operations.
- Actual World scaffold preparation preserves custom-Prelude semantics and
  authored warning provenance. Kept ordinary and activation paths still execute.
- Compiler fixture premises must be observed: private retained bodies, thin
  interfaces and public INLINE producers cannot substitute for one another.
