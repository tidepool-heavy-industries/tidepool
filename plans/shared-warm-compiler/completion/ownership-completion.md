# Compiler ownership completion

Accepted implementation contract, 2026-10-20; base `c14dad0f0c` on
`integration/compiler-query-warm-final`. Replaces the earlier ownership design;
retains the campaign G2/G3 gates in `plan.md`.

## Outcome

Carry issuing compiler owners through preparation, certification, materialization
and installation. Share immutable recursive-group code; instantiate mutable
runtime state separately. Available native bodies do not imply every sibling's
package closure is prepared. Completion belongs to actual selected demand.

Keep canonical acquisition, lazy Core recovery, corrected plugin-policy ordering,
SOURCE knot rehydration, fresh installation handles and retained publication
ownership. Replace cumulative stage snapshots, late witness reconstruction and
implicit live package reuse. No new generic cache, continuation registry,
authority factory or test framework.

## Stage completion

One private request-local stage input owner retains the immutable World basis,
the ACTUAL immediate predecessor and new completed additions. Recovery, TYPE
capture, Name/native association and certification consume this same owner.
Equal digests do not substitute for held executor/World/pending ownership.

Keep immutable canonical products separate from NameCache-bound hydration and
mutable attempts. Retain late canonical acquisitions selectively in the existing
completed dependency owner, not fake source memo rows. Share immutable values
with fresh mutable caches; do not retain completed HscEnv values.

Move private prefix advancement and completion issuance after certified-product
writing, within completeWorldProducts. Seal native/source products, type captures
and late canonical additions together. Failure leaves the stage unadvanced;
earlier stages remain private until existing whole-request success. Runtime
publication still requires actual compiler-close evidence. Selected Originals
must not replay through source.

## Exact native demand

Extend the existing selected-closure owner to coissue exact groups, hidden
retained-value requirements and ordinary package obligations in one traversal.
Resolve reached Original coordinates once against the SAME selected binding
pairs and permissions; carry the resolved owner into certification.

Represent available bodies, selected demand needing products, and ready
executable selection distinctly with private constructors. Unprepared package
code requests preparation; missing/corrupt previously sealed products refuse.
Full native availability is not package readiness. Later completion issues a
new immutable selection record, never mutates an earlier Original's facts.

Declaration publication derives runtime roots from actual AcceptedJoin. Remove
the independent retained-ID override which loses captures hidden in native
bodies. Haskell's directly observed captures remain separate evidence, not an
assertion that hidden native capture requirements are empty.

## In-flight dependency exchange

At the existing PreparedRecovery package-demand quiescence point, use a narrow
NativeDemand/NativeReply exchange within the SAME active scoped request:

1. Run the frontend once; batch actually reached opaque Original uses.
2. Rust's held RequestCompilerInputs/InventoryOperation resolves exact groups,
   retained roots and ordinary package obligations.
3. Return existing immutable products or exact package roots still needed.
4. Resume the SAME Haskell stack and recovery worklist; accumulate settled
   demands and compile only newly required package code.
5. Certify only after selected demand closes, then finish normally.

Fresh local groups remain local; incoming groups retain their issuing owner.
The resolver cannot run effects or nested compilation. The daemon relays frames,
not graph policy. No terminal-response reentry, whole-inventory projection,
persistent continuation registry or frontend replay.

Use a matched versioned event sum on the machine channel. Bind frames to actual
operation, World/input owner, stage and monotonic demand sequence; diagnostic
short hashes are not authority. One outstanding reply. Wrong, stale, duplicate,
unsolicited or malformed frames refuse.

One absolute admitted request deadline covers worker, relay and host resolution.
Retain preallocation frame limits; account cumulatively through existing operation
budgets and refuse repeated demands making no progress. Intermediate messages do
not count as terminal outputs or refresh deadlines. Cancellation/disconnection
must unblock BOTH worker and client readers: killing the worker does not unblock
a relay waiting on the client socket. Keep input custody through actual END or
retirement; EOF, demand delivery and process kill alone do not prove cleanup.

Implement daemon/direct scoped-transaction parity. Exchange-dependent World work
requires this capability before execution; the EOF single-shot route refuses it
without replay/fallback. Closed portable single-shot work keeps its contract.
Semantic refusal can return one failed terminal result followed by normal END;
malformed accepted framing poisons the transaction without replay.

## Package products and fresh installation

Use finalized recursive binding groups under exact defining package/compiler
provenance. Assign full private binder identities BEFORE filtering; selected
subset ordinals are not stable identities. Product identity includes canonical
body, ordered imports, defining provenance and code-affecting constructor/layout/
site/type/literal metadata. Exclude unrelated selected siblings and runtime
scopes, roots and CAF state. Preserve metadata through validated projection.

Use distinct validated package products in existing ArtifactEntry/materialization
and retained references, not a third registry. Packages grant no HOME/source or
runtime authority. Share CompiledProgram images through existing ImageRegistry
and compile election. Whole-package-closure identity is not the final boundary.

Closed preparation retains an opaque scope-neutral instantiation product with
exact images/products/import choices. Today's ScopedTargetImage embeds a
preparation scope and cannot be retained unchanged. Closed inputs admit no live
Existing imports. Actual installation binds fresh I/B, environments, roots and
CAFs without ambient selection, recompilation or re-resolution. Ordinary notebook
inputs may include explicit live values through their owning binding path.
SourcePrepared cannot erase its proof through raw code access.

Delete implicit live-package advertisement, resolution and publication across
startup, later cells and raw fallback. Delete cache-only RetainedPackage and
CodeExport variants and their recovery routes. No independent successful issuer
exists outside that cache. Real captured functions/values retain BindingEntry/
Retained authority and actual provenance. Absence of effect sites or captured
fields does not establish whole-program source independence.

Permission to replace A remains distinct from fresh B dependencies. Preserve
real captured-A/parent requirements. Frozen B source/spec/prompts ignore later
draft C. Keep provisional automatic-abort custody until reservation consumes it
into the actual retained publication guard.

## Publication and fixture repair

Keep one owner-held guard and one-use execution body. Record body results before
settling that SAME guard in place. Failed dispatch returns the SAME unrun body;
after execution starts, lost results are uncertain and cannot authorize replay
or invented restoration. Confirmation precedes notification; confirmed B survives
reply loss. Initial/Replacement are typed purposes with actual bootstrap/A+cutoff.

Repair shared fixtures through the existing production prelude:
ready_public_owner, begin_public_bootstrap, prepare/install,
publish_application_surface, bind_initial_generation. A failure flag cannot skip
it. Every distinct installation consumes its own ticket; only an exact unchanged
surface permits idempotent initialization. Preserve genuine early bootstrap
failure controls. Observe actual typed terminal results before deliberate result
loss; strict-Visible's cause is unknown until observed.

The passing lower protocol test can reuse the same unrun body, but does not prove
fresh candidates. Distinct candidates share immutable code and invoke actual
installation separately, with fresh leases/sites/state. Whole PreparedToolset
pointer equality is not a fresh-state oracle.
