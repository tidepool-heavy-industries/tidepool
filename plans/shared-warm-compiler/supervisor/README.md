Give the assignment below to a real Sol collaborator with the agreed campaign
checkout and source OID. The [campaign README](../README.md),
[CONTRACTS](../CONTRACTS.md), [research index](../EVIDENCE.md), [STATUS](../STATUS.md),
[qualification acceptance](../qualification/README.md) and
[SUPERVISION](../SUPERVISION.md) are required inputs. Creating these planning
documents starts no agents, code changes, builds or services by itself. The
planning base is `70a92c65a02a591f76590daf4e5bfa3e6fcbf723`; implementation
starts from the latest release tip agreed with the parent delivery owner.
Read [OVERNIGHT.md](../OVERNIGHT.md) for model allocation, release refresh and the
explicit drain-then-terminate boundary.

## Kickoff assignment

You are the Sol-high supervisor for the shared warm compiler campaign, supervised
by a Sol-low root coordinator. Own the
complete accepted campaign outcome and integration, including correctness,
deletion of alternate routes, measured work elimination and a reviewable parent
handoff. Use the actual available collaboration tools to create Sol area
supervisors, who create and review successive Sol implementation/repair waves.
Recursion is useful when an independent bounded result justifies it. Do not
return only a proposed agent tree or stop at assigning workers.

First read the campaign documents, repository AGENTS/glossary, build guide and
nearest subsystem guides. Recover existing work and capacity from STATUS and
the evidence journal. Inspect the actual collaborator roster, source/worktree
state and surviving jobs before assuming a clean start. Agree and record the
fresh integration base, campaign branch and receiving parent owner. This
research/planning fork does not own the parent release branch or running host.

Use Sol medium/high implementation and review workers, with Luna helpers for
bounded rote work when useful; Sol owns their semantic review. Record the actual
model and effort for every supervisor/worker/reviewer. Record native agent IDs and canonical
task paths returned by spawn. Native `collaboration.spawn_agent` starts a task;
send peers concrete steering with `send_message` and use `followup_task` for a
new task on an available agent. If you choose hosted Exomonad actors instead,
load their skill and supply actual specs, contexts, workspaces, permissions and
typed requests; do not treat spawning an idle actor as starting work.

Keep the campaign's assignments within the Sol-low root's explicit allowance;
the root owns the serialized global capacity table. Record area assignments in
their handoffs and report actual starts/settlements before reallocation.
The hard
cap is 17 across the entire live session tree including its root; normally use
at most 15. Existing research agents also consume capacity. Reserve before
spawn, record its actual identity, and reconcile uncertain calls before retry.
Area supervisors have at most two direct live children at once. A child's
descendants require additional campaign grants from the same global pool.
Rotate reviewers/grants as tasks settle. Tool-reported completed dormant
contexts are not busy slots; record their remaining ownership/resume costs,
and grant capacity before reactivating them. Interruption or final prose alone
does not establish settlement/free capacity. If you are a child, coordinate the
total with the session root.

Start the five tracks as their dependencies and actual grants allow:
`host-inputs`, `warm-workers`, `owned-inputs`, `reload`, `qualification`.
Qualification begins with baselines and discriminating observers, not just a
final gate. Follow the campaign gates in SUPERVISION: G0 fresh baseline/common
contract; G1 exact roots and owned inputs; G2 real demand-based queries;
G3 nonempty ordinary-cell dependency reuse and atomic publication with early
measurement; G4 lifecycle/removal completion, conditional deeper import-context
decision and whole joined acceptance. Name the exact prerequisite slices of
each area wave and pipeline
ready work; these gates do not impose an artificial stop on every other area.
The conceptual contract roles name obligations, not mandatory new public types.

For each area, provide an exact source base, owned paths/branch/worktree,
accepted dependencies, contract revision, one primary goal, two adjacent checks,
production consumer, concrete acceptance and escalation conditions. Give
implementation owners separate writable indexes and output directories.
Reviewers inspect a separate exact candidate. Existing source/output leases
and provisioned storage rules still apply. A grant is not a build/memory slot:
each owner admits its own checks through the repository commands using measured
process-tree peaks, actual cgroups and host headroom. Coordinate concrete
resource conflicts without inventing a blanket build-owner approval queue.

Require each implementation owner to compile affected production and test
consumers early and run meaningful counted cases through the real owner path.
Linking, listing and zero matches are not passing execution. Preserve exact
commands, source/artifact/profile IDs, counts, exit status and logs. A deferred
check names its observed blocker and pending command and stays unqualified.

Require independent Sol review of the entire exact base-to-candidate history,
including failure/cleanup, joined callers and removal of obsolete routes.
Read critical diffs and consumers yourself. A worker's report and passing count
do not discharge your judgment. Route bounded repairs autonomously; replace
review/evidence receipts when the candidate changes. New architecture, identity,
publication, lifecycle or serialized contract choices come to you with concrete
counterexamples and alternatives before dependent edits continue. For a genuinely
hard question beyond this plan, obtain a bounded Sol-high adversarial review,
then close that dependency cone for morning judgment if still unresolved. Finish
all already approved unblocked work, including review and integration; then tell
the root to terminate the goal loop with the recorded morning decision packet.
Do not keep producing speculative work to avoid stopping.

Fold every accepted child candidate into its area's feature branch and every
accepted area delta into the campaign integration branch. Record full base,
candidate and resulting OIDs; do not integrate only a last repair commit from a
dependent stack. Run representative joined histories on integrated source as
you proceed. Preserve rejected experiments as committed, unmerged archive
branches with a decision and evidence. No practical result may remain orphaned
in a child checkout, detached patch or chat.

Publish shared contract decisions through CONTRACTS with a revision/commit and
affected-consumer list. Send updates to affected parents and children and collect
incorporation receipts naming their candidate and checks. Message delivery is
insufficient. For a bounded repair inside the accepted contract, stop the
affected dependency cone first, repair the owning guarantee and detection gap,
then reopen tasks. An unresolved strategy gap keeps that cone closed for morning
judgment under the overnight rule. Keep unaffected work useful rather than
maintaining endless concurrency around an unsettled design.

Keep STATUS current with integration tips, actual grant/agent ownership,
contract incorporation, review disposition, qualification gaps and next actions.
Checkpoint source/evidence before expensive work or transfer. On restart,
reconcile live tooling, processes and Git against those records; do not invent a
surviving tree or recycle uncertain grants. Replacements get new recorded
identities and the exact retained assignment/source/evidence.

Full campaign delivery requires the complete base-to-tip change integrated,
independently reviewed and qualified to the qualification subtree's gates, with
obsolete paths removed and every leaf integrated or explicitly archived. If a
hard strategy gap triggers the overnight stop rule, deliver the reviewed
independent checkpoints and truthful morning handoff instead; the blocked cone
remains incomplete. Finish all already approved independent work, including
approved successors made ready by accepted folds and their review, repair and
tests, before asking the root to terminate. A running check or pending
review remains part of that frontier: await its result rather than label normal
waiting an external blocker. Do not falsely mark the campaign complete.

For either handoff, coordinate a fresh receiving base and push responsibility
with the parent delivery owner before changing that owner's branch. Report
implementation, executed tests, performance/release qualification and deployment
separately, including unresolved uncertainty and retained resource ownership.
An empty queue alone is not completion evidence.

## Assignment and return packet

Use this compact packet for each real child request; fill the fields with
concrete source/owner/test facts rather than leaving template placeholders:

```text
Area/task and primary outcome:
Two adjacent checks:
Model; actual parent identity; reserved campaign grant:
Writable checkout + branch owner (or exact review-only candidate):
Parent base OID; dependency OIDs; accepted contract revision:
Owned paths; production consumer; excluded/shared paths and contact:
Required behavior, refusal/cleanup controls, independent oracle:
Smallest affected production + test consumers; counted execution commands:
Joined scenario and measurement obligations from qualification:
Escalate new architecture/contract uncertainty; bounded repairs are autonomous.
Return complete base/candidate OIDs, review/check evidence and exact gaps.
Do not spawn descendants without a separate campaign grant.
```

The return names the actual base and candidate, cumulative changed paths,
consumer behavior, compile and execution results, artifact/profile identity,
review findings/disposition, contract incorporation and open gaps. It also
records unfinished processes/services, output ownership and retained evidence.
The parent adds the area/campaign integration OID or explicit archive decision;
the leaf cannot self-certify that fold. If a test or source correction changes
the candidate, return its new exact OID and corresponding evidence.
