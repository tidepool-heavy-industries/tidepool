The coordinator assigns worker slots under [campaign supervision](../SUPERVISION.md#capacity-belongs-to-the-whole-tree),
including its whole-tree grants and per-area child limits. This plan creates no
extra concurrency allowance or permanent worker count.
Use independently scoped assignments when another result justifies a worker:

frontdoor, expected observations, accepted policy decisions, evidence destination
and a stopping/escalation condition. Test changes use a separate checkout from

coordinator's workspace. A build process is admitted separately from an agent.

## Verification waves

1. **Establish the baseline and detection gap.** Inventory existing execution
   targets/resources; reproduce the current packaged paths and independent root
   policy expectations before measuring a rewrite. Record the stronger Persona
   case as pending until its exact executed result arrives. Compile joined API
   consumers early, including `cfg(test)` and integration callers.
2. **Verify every implementation fold.** After host selected-state changes, run
   append/shadow/fork and root-policy histories through the real next request.
   After reference/delta transport changes, add cold realization, expiry and
   accepted-loss controls. After worker realization/frontend changes, run
   alternating worlds, imports/instances/TH and post-END capture. After reload
   changes, run blocked/forced/partial retirement and cold recovery. Each fold
   needs a small integrated production history now, not only a final release run.
3. **Decide the frontend experiment explicitly.** Join semantic and measurement
   results from [the import-context experiment](../warm-workers/03-import-context-experiment.md).
   Reject an unsafe or ineffective arm; retain the accepted lower-level gains
   and name the remaining ordinary-module scope cost. Do not retain an
   unaccepted bypass or call root lookup O(delta) frontend evaluation.
4. **Qualify the integrated bundle.** Run scaled comparisons and existing
   packaged Persona/coding/reload/capture gates from one exact frozen source,
   profile, compiler and asset contract. The final recommendation separates
   accepted behavior, qualified timing, unmeasured boundaries and deployment.

## Evidence and decision contract

Retain source/submodule revisions, actual artifact hashes, commands, selected and
executed counts, terminal status, trace/capture assessments and cleanup outcomes.
Use private `/srv/swarm/evidence/inanna/` storage; source contains maintained
properties and compact current decisions, not private conversations or raw logs.
An inaccessible observation is not absence; omitted timing is unknown, not zero.
Compilation, test discovery, execution and performance qualification are separate
statuses. No skipped/zero-match selection qualifies behavior.

The root-policy regression and its shared-helper oracle failure are mandatory
controls throughout the rewrite. Equal interfaces, retained custody, selected
Original roots, exact required children and current executable demand stay
independently observable. See [the baseline plan](01-baselines-and-oracles.md).

Performance acceptance uses measured removal of repeated work and reported
latency/memory/IO consequences at the actual integrated source. There is no new
mandatory 10× threshold here; do not dilute any separately accepted product gate
in another plan. A 10× ambition needs a current critical-path decomposition and
scaled structural evidence, not historical arithmetic or cache-hit counts.
