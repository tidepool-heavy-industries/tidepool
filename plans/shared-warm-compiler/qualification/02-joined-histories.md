# Joined histories at every fold

Verify the actual transition from one published scope through request admission,
worker work, END settlement, sealing, execution/publication and the next request.
Use [independent semantic expectations](01-baselines-and-oracles.md) and extend
existing production-path fixtures. Passing a component helper or manufacturing a
certificate cannot establish this sequence.

## Integration cadence

The qualification lead tracks the exact integrated candidate and assigns the
smallest discriminating joined history after each material fold. Implementation
owners compile affected production/test consumers first. Independent review
checks the combined diff and alternate callers before a broader run. Failed
histories block acceptance of their owning boundary; do not defer the first
real compiler/host execution until all implementation work is complete.

| Joined fold | Early executable history and observation |
| --- | --- |
| Baseline/detection repair | Run both explicit Original winners and the required-child conflict through real input issuance/selection. Run startup → memory/files → later pure cell using the real shared workspace |
| Selected host roots/indexes | Publish A; capture child; append/shadow in parent and child in both orders; next requests observe their exact roots. Full recomputation agrees; unrelated siblings neither invalidate nor gain visibility |
| Reference/delta transport | Register exact input; hit it; expire/evict registration; cold bootstrap that same input. Distinguish known preacceptance miss from accepted response loss, without retrying uncertain source work |
| Worker realizations | A→A→B→A worlds on bounded workers; same actor changes world and different actors share a world. Evict/replace worker; exact cold reconstruction agrees with the hot result |
| Frontend entry experiment | New tiny ordinary modules over retained scope, including imports/instances/defaults/TH; compare complete products and refusals under all accepted arms before packaged expansion |
| Post-END and runtime publication | Clean END then cancel; failed install/publication; completed execution intent followed by metadata restage. Check no private successor selection, wrong END borrowing or effect replay |
| Reload/adoption | Candidate failure, default blocked, forced confirmed retirement, partial/uncertain cleanup and cold restart. Verify generation fence, exact affected set and independent actor worlds |

Run one small representative packaged history as soon as the joined host/worker
path can support it, then retain that canary at subsequent folds. Final expanded
rosters complement these early checks. A compile-only parcel remains unqualified
until its behavior has crossed the joined consumer.

## Reload and retirement controls

The root design records the adopted policy explicitly. For the planned
whole-generation retirement contract, carry these outcomes through the existing
reload preparation, generation fence, runtime resource owners and publication:

1. A candidate that fails preparation/typechecking stops no dependent service
   and leaves the selected world operational.
2. Default reload with affected live non-LLM services returns typed blockers
   naming real references/incarnations and source versions. The selected world
   and services remain usable. A new blocker appearing after advisory discovery
   is caught at the admission fence.
3. Explicit force cancels/drains only the actual affected generation-owned
   non-LLM services/callbacks/parked resources. Independent LLM actors and forks
   remain on their own selected worlds. Missing PIDs or cache eviction are not
   cleanup proof.
4. After the fence, previously issued but unexecuted old policies cannot start
   new old-generation compiler/install/source-dependent registration work.
   Already admitted work and completed receipts settle under their actual
   owners; independently authorized source-neutral operations remain permitted.
   An old request cannot overwrite the newly selected root.
5. If X stopped but Y did not settle, report X stopped and Y remaining/uncertain
   even if replacement publication is refused. Do not describe this as an
   unchanged rollback or automatically restart X.
6. Self-reload preserves `Continuing` and settles the reload before returning
   its ordinary answer, without waiting for its own initiating continuation.
   Already compiled pure code, independently authorized source-neutral IO and
   receipt settlement may continue. Fresh old-generation compiler/install/
   source-dependent registration authority refuses at its actual owner. Do not
   assume Haskell terminates after the receipt or bound physical custody by an
   invented coordinator lifetime; retain old code/type/dictionary support until
   actual completion or cancellation. A continuation failure cannot erase an
   already committed reload.
7. Transfer an issued policy through `SourceCallback` with `generation() == None`,
   then attempt callback activation/new source-dependent registration after the
   fence. The actual carried source dependency must refuse despite the missing
   optional accessor. Pair it with a genuinely independent source-neutral read
   and already prepared receipt display, which remain allowed under their
   existing grants. Force acts on the actual affected set at the fence; it does
   not require a second approval receipt or a previously previewed exact list.

The current coherent-reload acceptance intentionally permits a late new call
through a retained generation-A policy after B is published. Retirement changes
that observable behavior: replace that positive late-call assertion with a typed
retirement refusal, while retaining fresh-B notebook isolation and prior
admitted-work settlement controls. Record this migration decision; do not keep
incompatible old/new assertions or weaken every old-generation check.
