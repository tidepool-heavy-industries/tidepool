## Ownership rules

- Structural tests construct current typed data. They do not issue compiler
  authority. Exhaustive encoders and required fields make schema drift visible.
- Buck generates immutable compiled fixtures from declared source, compiler,
  package, target and ordered-root inputs. Tests consume runtime resources,
  rather than embedding generated blobs in Rust executables.
- Production compiler, admission, actor and resource owners issue execution
  authority. Tests use these entrypoints for success and recovery claims.
- Rust browser projections own generated schemas, TypeScript types and runtime
  validators. Truly opaque tool/provider data remains explicitly opaque.
- One matched release bundle owns compiler/runtime/assets/schema identities.
- Lexical/interface closure, compile-time executable closure, runtime body
  demand and runtime resource custody are distinct. Preserve original typed
  identities and owner-issued facts; never reconstruct a complete view from a
  narrower one.
- Negative codec and historical rejection fixtures remain valid, but every
  semantic refusal case first establishes a valid control.

## Test strategy and completion requirements

Use the existing Buck providers, Tasty trees, Rust libtest targets and shared
test-data/testing/corpus owners. Each test must state which contract it proves:

| Contract | Fixture and assertion |
|---|---|
| Codec and data structure | Current exhaustive owner encoder plus bounded typed inputs; round trips, identity laws and deliberately malformed mutations. No execution authority or GHC startup. |
| Haskell language semantics | The same authored module graph through pinned GHC and Tidepool; compare acceptance, relevant failure category or result. Check import-graph premises. |
| Tidepool authority and lifetime | Genuine compiler products and production admission; vary one authority, dependency or lifecycle event, retain its exact result, and prove recovery. |
| Product acceptance | Scripted provider transport with real host, resident Haskell, Store, scheduler and resource owners; observe durable outcomes through the deployed bundle. Live provider/browser trials follow. |

Negative semantic tests establish a valid control and fail for the intended
reason. A filesystem error, malformed fixture or arbitrary `SomeException`
cannot count as language rejection or authority enforcement. Properties such
as order independence, alpha-renaming, changed nominal identity, round-trip
preservation and bounded decoding belong in existing QuickCheck/proptest or
table-driven suites at their owning pure boundary. They complement actual
compiler and lifecycle scenarios rather than replacing them.

Share immutable fixture captures through ordinary scoped test resources and
declared Buck artifacts. Give each case fresh mutable state and each delivery
fresh request storage. Cases remain independently selectable; selecting one
case must not run earlier tests as hidden prerequisites. Keep compilation,
executed named cases, internal assertions and end-to-end acceptance separate
in reports. Preserve existing broad integration/corpus requirements; do not
turn every local repair into a full-cohort rerun.

Complete the already approved removal of duplicated positive wire builders:

- Replace `candidateCompactInventory`/`structuralCandidate` manual packets and
  `FixtureInventory`/`compactInventoryRows` with codec-only scenarios emitted
  by the existing Rust inventory/manifest owner. Keep the Haskell reader under
  test and preserve bounds/collision controls.
- Replace `FinalizedCoreTest.captureProof` positive certificate/candidate
  encodings and numeric-position positive purpose payloads with owning
  encoders. Any claim about authenticated admission uses genuine certification
  and protected reservations, not synthetic codec data.
- Remove `exactCompilationCacheSafety`'s partial CBOR/JSON parser and semantic
  certificate/compile-input field walkers. The existing production readers
  provide the facts; raw layout inspection remains only for codec tests.
- Retain deliberate malformed and historical-version rejection cases. Their
  invalid bytes are the subject of the test, never a positive fixture format.

These deletions remain full-migration obligations. If a first-delivery gate
