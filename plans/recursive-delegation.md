# Recursive delegation implementation

## Accepted direction

Replace WorkPlan with live scaffold → unfold → checked integration → next ready
batch. Sol Medium owns shared cross-component decisions; Luna owners recursively
scaffold and delegate implementation through subcomponents to microtask leaves.
Aim for at least three Luna implementation levels on average, with useful parallel
work. Explain a terminal leaf before substantial direct implementation. Review
leaf changes and component joins at their respective boundaries.

This is the canonical execution workflow across core developer instructions,
workspace roles, project overrides, skills and examples. It is not an extra
optional technique. Keep explicit user model placement and runtime authority.

## Owners and implementation

- `Project.Work`: Luna lead constructor, exact-candidate manual review admission.
- `Project.Routing`: batch admission plus retained original handles/collector;
  configure event routing after admission without readmitting children.
- `Project.ReviewFlow`: counted checks, exact-source review, one bounded repair
  budget and optional publication through the existing `Project.Merge` owner.
- `Project.DecisionAnswers`: bounded selection among current owner-supplied
  decisions. Relays do not alter assignments or source. New, stale, conflicting,
  uncertain or failed answers retain the owner's question notice. No watchdog.
- Core prompts and shared/project role prompts make recursive execution the
  default. The compiled recursive-work procedure is the discovery entry point.

Remove WorkPlan, its interpreter, verification wrapper and obsolete recipes.
Preserve context checkpoint primitives and existing source/review failure cases.
Mixed result types remain ordinary Haskell results, without fabricated commits.

## Verification and release

Use isolated worktrees and one compiler slot. Exercise real resident admission,
nested batches, a later batch, original request ownership, pending-close refusal,
checked review/repair, integration outcomes and decision guards. Scripted model
replies do not establish native-model adoption. Recipe hosts without notification
delivery must preserve `NotificationUnavailable`; never report it as a sent answer.
Prepare and replay live synthetic Jev packets separately from actor routing tests.

Run catalog/documentation checks, sync the template and pins, then build the
matched executable. Keep wave20 on its existing pin. Its WorkPlan trial was
explicitly withdrawn. It completed product integration at `0feefcb6` and retained
its final interview and cleanup handoff through `4d8e11c`; this implementation
does not reinterpret that run as a recursive-delegation trial.
Do not overlap runs or launch merely because implementation time has elapsed.

## Evaluation

Measure useful implementation depth, overlap, first useful fork, dependency
waiting, source corrections, independently found defects, parent relay rounds and
elapsed time to checked delivery. Count neither reviewers nor idle forwarding
actors as implementation depth. Structural simplification is not a measured
wall-clock improvement; compare actual accepted outcomes in subsequent runs.
