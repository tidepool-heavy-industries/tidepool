# Workbench acceptance

The current callable contracts live in the owning source, shipped API guide and
workspace WORKBENCH.md. Validation of the integrated revision must compile changed
consumers and execute focused command, request, fork, routing, review, tool-dispatch
and cleanup failures. Example registration and compilation alone are not executed
acceptance. Retain exact source, commands, matching test counts and cleanup receipts.

The engine's M1/M2 and host acceptance plans remain authoritative for pending
cells coexisting with later tool activity, exact continuation resumption without
replay, invocation/result identity, overlapping binding visibility, cancellation,
retained cleanup races and captured publication without self-dependency. This
workbench migration does not establish those live adapter gates or redesign the
engine. Active delivery and release obligations remain in the engine/host plans.

Live model adoption, three-wave workflow evaluation and measured performance
savings remain separate from source integration. Retained wave and automation
reports contain the prior experimental evidence and deferred observation/cache
proof obligations. Structural savings do not prove latency or throughput gains.

Confirm normal-request and command ownership transfer, waiter cancellation,
completion-versus-cancellation races and terminal resource retirement through the
existing lifecycle owners. Missing command release or retirement-purge evidence
remains a gap until an executed owner check establishes it. Preserve imported
plans/next/WaveContract.hs and the engine fixtures.

Typed assertion helpers, notebook indentation assistance and Jev pattern quality
remain possible scoped experiments with no accepted new abstraction. Old unconsumed
workflow frameworks and duplicated implementation plans are removed deliberately;
their removal does not count as successful evaluation of those experiments.
