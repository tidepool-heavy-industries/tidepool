# Notebook cells and lookup

## Product contract

Two substantial Sol-owned recursive lanes deliver together before a new dogfood
swarm. Haskell is a persistent notebook-style script: declarations form one
mutually recursive group; statements execute in order; every expression displays.
The entire cell checks before user effects or binding installation. Runtime
failure retains the committed prefix. Declaration installation is the first
execution step. Later definitions shadow through existing identity mechanisms.
Declarations cannot capture same-cell statement bindings; suggest let or a later
cell. respond is terminal and later items do not run, not a static rejection.
No colon meta-commands remain in cells.

lookup is batch-shaped discovery in Haskell vocabulary: names and :: type queries,
against what the next cell can name. Return signatures/declarations, ambiguity
candidates, live-binding provenance and per-query outcomes. Support useful
polymorphic matches and wildcards, exact matches first; no fuzzy-search or Haddock
dependency required. Canonical input is {"queries":[...]}; lenient raw-string
acceptance is contingent on the real hosted boundary.

last means latest displayed result, unchanged by rejected/no-display cells.
last.more is a typed continuation, not a receipt ID. Multiple displays do not
require a heterogeneous cell-result concept. Define continuation advancement and
display exceptions before implementation. Automatic Generic does not imply all
GADT/existential declarations can derive it.

## Integration waves

1. Parallel lane readbacks and feasibility probes; agree source-item IDs/spans,
   execution grouping, non-mutating checking, authoritative scope and tool owners.
2. Checked local scaffolds unlock recursive implementation frontiers. Notebook
   integrates compiler/runtime; lookup integrates resolution/search/hosted output.
3. Corpus inventory starts early; final migration follows stable interfaces.
   Notebook owns cell idioms, lookup owns lookup examples; coordinator owns common
   registration and harness wiring. Remove old meta-command fixtures and vocabulary.
4. Real hosted consumer: declare a type, launch/bind, inspect by name/type, invoke
   a returned function next cell. Repeat after rejection and partial runtime
   failure, including recovery, terminal respond and command output pagination.
5. Focused tests, relevant integrated suite, formatting and diff checks; exact
   resulting-source review. Only then launch fresh actors with the new frozen
   corpus. Current .shoal definitions stay frozen; update shipped sources for
   next swarm, not the current runtime package.

## Acceptance

Use documentation_tests and actual hosted tools, not only generated strings:
mixed declarations/two statements/display; downstream-fixed numeric and monadic
binder types; late type error executes nothing; runtime failure preserves prefix;
quasiquotes/multiline strings with column-one content and blank lines; where
layout; let sees earlier bind; declaration capture gets actionable error;
respond skips tail; shadowing/recovery preserve nominal identity; Generic without
duplicate instances and documented exceptions; bounded display last.more returns
command next page; lookup batch isolates failures and wildcard query finds a
function subsequently invoked. Diagnostics retain source spans; receipt summarizes
declarations/statements/displays and distinguishes source items from execution
steps. Promise all produced diagnostics, not all conceivable GHC errors.

Corpus primes coherent multi-step cells, not a literal prohibition on examples
that could also execute line by line. Audit prelude helpers and hot-set Haskell
signatures. Tool description stays within actual enforced size.

Measure console canary rounds/candidate, rejections/worker, multi-item fraction,
mean declarations/cell with comparable conditions and explicit missing coverage.
Stage 2 is deferred unless a checked simpler route preserves the complete contract.
