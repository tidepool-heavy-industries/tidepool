# Compiled-cell evidence map

Static source audit of revision `cedb5f978a06a1170ebacc928577075a24b79fa5` against [engine-compiled-cell-delivery.md](engine-compiled-cell-delivery.md). This records test entrypoints and their visible boundaries; no tests or builds were run for this audit. A named test is not treated as executed evidence unless its runner, required environment, and retained result are identified.

## Current production route and direct evidence gap

The admitted actor route is `ResidentActorWorkbench::prepare_cell` → `prepare_admitted_cell` → `parse_cell_plan` → `compile_cell_program_admitted` → `begin_cell_program`, with item execution prepared only after the `CellProgram` is returned. The callsites are in `exomonad-actor::resident_workbench`; the compiler entrypoint is `tidepool-runtime::session::turn::compile_cell_program_admitted`.

`turn_scaling_tests::execute_cell_with_authority_checks` directly calls `compile_cell_program_admitted`, starts the sealed program, consumes each item/display without further compiler submissions, and publishes through the selected ephemeral or durable owner. `complete_cell_consumes_item_and_display_without_compiler_requests` exercises a real multi-item source and checks missing/wrong deployment refusal before worker submission. These are runtime-session tests of the compiler/program/publication helpers, not actor `prepare_admitted_cell` integration tests. The older worker-gated inference fixtures below still check/pin and manually invoke per-item turns; they establish inference and type-pin behavior, not the complete admitted route. Actor tests using `ResidentActorWorkbench::new` exercise the no-authority split route, not `prepare_admitted_cell`.

## Tests that look stale when cited for the new route

- `resident_workbench::tests::single_bind_item_cell_folds_into_one_daemon_round_trip` and `two_item_bind_cell_keeps_two_daemon_round_trips` intentionally exercise `ResidentActorWorkbench::new` without compilation authority. They document legacy split/per-item semantics; do not cite them as acceptance for the admitted `CellProgram` path.
- `turn_scaling_tests::protected_growing_prefix_*` now exercises complete-cell compilation and consumption, but only with ephemeral publication. Its B/N matrix is not durable publication/recovery evidence.
- The ignored `cell_compile_cost_measurement` is an older live-daemon report-only baseline. It does not establish the planned optimized production performance gates.

Tests that merely *name* replay, source, or old recovery formats are not automatically stale: the recovery acceptance test compiles a new consumer after hydration, and unsupported-format tests correctly assert typed refusal while retaining the bytes. Declaration candidate staging may regenerate source from recorded compiler receipts; that is publication input generation, not replaying effects to reconstruct recovered values.
