# Generation lifecycle controls

The quoted-generation fixture prepares genuine compiler products. Its retirement
component controls use unavailable resident inventory and an explicit component
decision. They do not issue a staged Reload report or qualify automatic Reload.
All publication controls first initialize their actual public/source owner and
consume each installation's own bootstrap ticket. Fault injection happens at
the selected generation publication boundary, after that shared preparation.
Shared prepared-code identity is distinct from the separately issued dispatch
custody and installation lease. These checks do not replace runtime site-origin
or mutable-state isolation histories.

| Existing control | Contract it exercises |
| --- | --- |
| Foreign target before cutoff | Actual reservation refuses a foreign target fence while A remains unchanged. |
| Owner loss before send or queued receive | No reservation/source effect is inferred from an unaccepted command. |
| Owner loss after reserve, panic, lost waiter, disposal panic | The same candidate, reservation and source fence survive under native cleanup custody. |
| Owner loss after capture | FIFO capture retains actual population and physical ownership without initiating a stop. |
| Body refusal and linked cancelled body | An executed body returns its own refusal and obligations; this is not command nonstart. |
| Native recovery of linked result | Native cleanup consumes the same actual body result, preserving physical obligations. |
| Crossed source receipts and partial reopening | Only the same reservation's source receipt can discharge it; partial A restoration remains refused. |
| Captured-A refusal followed by lost body delivery | The generic candidate retains A. Its actual typed failure must name that same fenced source before the result is discarded. Compact failure metadata cannot authorize reopening: the core retains the guard, both source gates stay closed, and notification remains unconfirmed. |

Retain these component controls when changing the publication protocol. A
component pass does not establish successful hosted Reload, force, complete
physical cleanup, or cold recovery. Failed histories remain unqualified until
their intended assertions execute.

Command-nonstart coverage belongs at the actor-owned publication boundary: use
an actual reservation/fence, a real refused transport returning the same unrun
body, the owner-held guard, and an ordinary acknowledged operation diagnostic.
Do not attach a fabricated Reload report, create a capture, or bypass automatic
policy to make a component fixture resemble the hosted path.

The named `actor_generation_publication_protocol_tests` target exercises that
lower production reconciliation boundary with three actual prepared replacements.
It returns a body through a stopped supervisor, loses an actual diagnostic journal,
and loses the real result after the driver accepts and completes its body. That
third history does not require or establish visibility or independent B source.
It creates no Reload report, capture, or STOP command. Its source restoration and
evidence assertions do not establish physical cleanup or successful hosted Reload.

The separate `actor_initial_publication_protocol_tests` target uses actual
Ephemeral and Durable initial preparations. Each is cancelled before committing
and executed through a live publication supervisor. The real returned refusal and
borrowed initial settlement feed the production failure classifier. The Durable
body's retained obligations must remain recovery-required; the settled Ephemeral
body can discharge. The test creates neither a predecessor nor a cutoff.

The host's coherent reload histories use the real source staging owner and the
authored tool. The frozen-source history must execute a new B cell after A's
cutoff and a later disk C edit; a publication receipt alone is insufficient.
The caller-loss history waits for the real operation's confirmed B receipt before
dropping its unconsumed reply receiver, then observes the retained receipt and
executes B. This does not deterministically exercise a failed sender. The private
notification component separately counts attempts at the actual lifecycle send
boundary, including repeated observation after confirmed recipient shutdown.
