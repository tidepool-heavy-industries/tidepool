A replaced Haskell machine creates a successor actor incarnation. Old handles,
closures, materialized values, replies, and watch projections are never silently
revived. Use the `status` tool's `recovery` view for replayed declaration source
and losses, then its `bindings` view for the successor's actual names.

Operational receipts may prove an earlier effect committed, but Tidepool never
replays an effectful cell after loss. Preserve important decisions and Git
evidence in the repository. If a handle was lost, inspect its receipt and runtime
state before deciding whether to issue new work.

Provider failure does not settle an actor request or imply process death. The
detailed status view reports provider health and requested versus confirmed
settings. Do not blindly steer a provider-rejected conversation; use typed Shoal
communication and explicit retirement after inspection.
